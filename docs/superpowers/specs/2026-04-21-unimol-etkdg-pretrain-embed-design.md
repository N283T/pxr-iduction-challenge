# Design: Uni-Mol v2 × ETKDG Pretrain-Embed (strategy-3 on Uni-Mol)

- **Status**: Proposed (2026-04-21 evening)
- **Author**: Claude Code session, brainstormed with user
- **Related**:
  - Parallel to Boltz trunk strategy-3 spec (`2026-04-21-boltz-trunk-log2fc-pretrain-design.md`). The two plans are independent and can run concurrently.
  - Prior memory note `project_protein_ligand_coupling_nn_weak` (2026-04-19) explicitly flags "**Ligand-pose-only models (Uni-Mol v1) NOT covered**" as unexplored territory. This spec addresses that gap via v2.
  - Completes "Buterez strategy-3 applied to every available backbone family" (chemprop / molformer_c3 / kermt / attentivefp / gatedgcn / **unimol** / boltz).
  - Uni-Mol is the first **3D-structure-aware** pool member (not counting Boltz trunk which is protein-ligand joint).

## Goal

Apply the pretrain-embed recipe to Uni-Mol v2 via `unimol_tools`. Use **ETKDG conformers consistently for both pretrain and inference** to avoid distribution shift (user-chosen Path 2). All 13,136 compounds are covered — no Boltz coverage restriction. Expected: a new pool member with decorrelating signal from 3D ligand geometry.

## Rationale

1. **3D-structure-aware member not yet in pool**. Current 8-pool is 2D descriptors + graph embeddings + Boltz protein-ligand trunk. No pool member consumes ligand 3D coords directly. Uni-Mol v2 fills this niche.

2. **`unimol_tools` API is high-level**. `UniMolRepr(...).get_repr(smiles_list)` extracts CLS-token representation out of the box. Pretrain on log2_fc via `MolTrain(task='regression')`.

3. **ETKDG conformer consistency (Path 2)**. Uni-Mol v2's own pretraining uses RDKit-generated conformers (≈ ETKDG). Using ETKDG for PXR pretrain AND inference aligns with native model distribution. Paths 1 (pretrain-ETKDG → inference-Boltz) and 3 (no pretrain) documented as alternatives but deferred.

4. **Full 13k coverage**. Unlike Boltz strategy-3 which requires extending trunk to 8,483 additional compounds (~12-24h background run), Uni-Mol's ETKDG path generates all 13k conformers in ~30 min.

5. **Pool diversity bet**. Boltz trunk is in pool as protein-ligand joint; Uni-Mol would add pure ligand 3D signal. Different information path even though both are "3D-aware".

## Non-goals (deferred)

- **Path 1 (ETKDG pretrain + Boltz-pose inference)**: distribution shift risk with Uni-Mol's ETKDG-pretrained backbone. Worth A/B vs Path 2 later if Path 2 succeeds.
- **Path 3 (no log2_fc pretrain)**: generic Uni-Mol repr directly to TabPFN. Cheap sanity check; run if Path 2 is delayed.
- **unimolv1 (84m)**: paper out-of-date vs v2; v2 has 5 size options and improved architecture. Use v2.
- **Uni-Mol v2 Complex (protein-ligand joint)**: different model, different recipe. Out of scope.
- **Custom conformer injection (Boltz pose passed as dict input)**: possible via `UniMolRepr.get_repr(data=dict(atoms=..., coordinates=...))`, but Path 1 domain shift risk. Defer.

## Architecture

### Tool stack

- **Package**: `unimol_tools` (v0.1.3.post1, archived in Uni-Mol repo; replacement `https://github.com/deepmodeling/unimol_tools` maintained separately)
- **Repo clone**: `~/ghq/github.com/deepmodeling/Uni-Mol/unimol_tools` (already present)
- **Pretrained weights**: auto-downloaded from HuggingFace `dptech/Uni-Mol-Models`
- **Model**: `unimolv2`, `model_size=84m` or `164m` (larger = richer but slower; default 164m for quality)
- **Conformers**: ETKDG (v3), generated by `unimol_tools` internally when given SMILES input, OR pre-generate via RDKit for explicit control

### Environment isolation

Uni-Mol's deps (DGL, specific pytorch, rdkit<numpy2.0) may conflict with main pixi. Strategy (same pattern as KERMT PR #103):

- Clone: already at `~/ghq/github.com/deepmodeling/Uni-Mol`
- New: **separate pixi project** in `~/ghq/github.com/deepmodeling/Uni-Mol/unimol_tools/`:
  ```
  cd ~/ghq/github.com/deepmodeling/Uni-Mol/unimol_tools
  pixi init
  # port requirements.txt into pixi.toml
  pixi add --pypi unimol_tools
  pixi add --pypi huggingface_hub
  ```
- Main pixi env untouched
- Uni-Mol runs output npz/parquet → main pixi consumes

### Phase 1: ETKDG conformer pre-generation + Uni-Mol pretrain on log2_fc

**ETKDG source optimization (user finding 2026-04-21 evening)**:
Boltz-2 preprocessing already caches ETKDG pre-diffusion conformers at
`structures/boltz2/outputs/boltz_results_inputs/processed/mols/<id>.pkl`
(dict form `{"LIG1": RDKit Mol with 1 conformer}`). 4,652 compounds
already have cached ETKDG structures — we can reuse them directly.
Remaining 8,484 compounds (13,136 - 4,652) require fresh ETKDG
generation via RDKit.

Benefits:
- Saves ~8 min of ETKDG recomputation
- **Exact reproducibility** for the Boltz-covered subset (identical ETKDG
  seed/params to whatever Boltz used internally)
- Enables clean Path 1 vs Path 2 comparison later (same ETKDG, different
  final coords)

**Two sub-options**:

**Option A (simpler, default)**: Pass SMILES list to `unimol_tools.MolTrain`. It generates ETKDG conformers internally and handles everything. Drawback: ignores our cached Boltz ETKDG.

```python
from unimol_tools import MolTrain

clf = MolTrain(
    task='regression',
    data_type='molecule',
    model_name='unimolv2',
    model_size='164m',
    epochs=30,
    batch_size=32,
    metrics='mae',
    target_col_prefix='log2fc_',  # adjust
)
# data: pandas DataFrame with SMILES + log2fc_8p25 + log2fc_33 columns
clf.fit(data=pretrain_df)
# Saves checkpoint to ./exp/{timestamp}/
```

**Option B (hybrid, recommended)**: Build a unified conformer bank:
- Load 4,652 Boltz-cached ETKDG from `processed/mols/<id>.pkl["LIG1"]`
- Generate 8,484 new ETKDG via `rdkit.Chem.AllChem.EmbedMolecule(mol, AllChem.ETKDGv3())`
- Pass as dict `{atoms: [...], coordinates: [...]}` to Uni-Mol (custom conformer route)

**Option C (fully explicit)**: Regenerate all 13,136 ETKDG via RDKit, ignore cached. Safest for uniform reproducibility but wastes ~8 min.

**Recommendation**: **Start with A** (simplest smoke), pivot to **B** (cache reuse) if A works. Skip C unless A+B both fail.

### Phase 2: Extract CLS representation (frozen)

After pretrain, load finetuned model and extract `cls_repr` for all 13,136 compounds:

```python
from unimol_tools import UniMolRepr

# Load finetuned (needs checkpoint path; unimol_tools's MolPredict handles this,
# but for repr extraction we may need to customize — verify during implementation)
# Fallback: use pretrained UniMolRepr directly if finetune-to-repr doesn't work cleanly
repr_model = UniMolRepr(
    model_name='unimolv2',
    model_size='164m',
    # optionally point to the finetuned checkpoint via UNIMOL_WEIGHT_DIR env var
)
repr_output = repr_model.get_repr(data=all_13k_smiles_list)
embeddings = np.array(repr_output['cls_repr'])  # shape (13136, embed_dim)
```

Save as `data/unimol_v2_log2fc_embed.parquet` (indexed by compound_id).

**CLS repr dimension** (from `unimolv2.py`): depends on `encoder_embed_dim` of chosen model_size. For 164m: likely 512d. Confirm at runtime via `embeddings.shape[1]`.

### Phase 3: TabPFN 5-fold on embedding

Same pattern as other strategy-3 members:

- `run_train.py --model tabpfn --feature unimol_v2_pretrain_embed --split umap --trials 0`
- Experiment name: `tabpfn_unimol_v2_pretrain_embed_umap_default`
- Gate: single-model OOF MAE ≤ 0.48
- Pearson r < 0.95 vs existing 8-pool members (slightly looser since Uni-Mol is a different family)

### Phase 4: Ensemble integration

Two options:

- **Add-9**: append `tabpfn_unimol_v2_pretrain_embed_umap_default` to ENSEMBLE_MODELS, grow pool to 9
- **Swap**: replace a weak existing member (e.g., `tabpfn_gatedgcn_pretrain_embed_umap_default` at current weight 0.019) with unimol. Maintain pool size 8.

Bakeoff both. If swap gives lower MAE, prefer swap.

## Data flow

```
compounds.std_smiles (13,136)
    ↓ Uni-Mol pixi env: MolTrain(task=regression, labels=log2fc 2-head)
        (ETKDG generation + pretrain continued on log2_fc, ~2-4h GPU)
[checkpoint: ./exp/{ts}/model_best.pt]
    ↓ UniMolRepr.get_repr on 13,136 SMILES
[repr_output['cls_repr']: (13136, ~512)]
    ↓ save → data/unimol_v2_pretrain_embed.parquet
    ↓ main pixi: register unimol_v2_pretrain_embed feature in run_train.py
    ↓ run_train.py --feature unimol_v2_pretrain_embed
[DB: tabpfn_unimol_v2_pretrain_embed_umap_default]
    ↓ ENSEMBLE_MODELS update (add or swap)
    ↓ run_ensemble.py + run_ensemble_calibrate.py
[ens_caruana_bag20_calibrated_best.csv]
```

## Acceptance criteria

1. **ETKDG conformer generation succeeds on all 13,136 compounds** (tolerance: <1% failures, documented).
2. **Uni-Mol pretrain converges** on log2_fc val loss (val MAE decreasing).
3. **Single-model OOF MAE ≤ 0.48**.
4. **caruana_bag20 weight > 0**.
5. **Pool MAE ≤ current 0.4185 (8-pool baseline)** after add-9 or swap.
6. **Pearson r with existing 8-pool members < 0.95**.
7. **ruff clean** on main-pixi scripts.

### Failure handling

- **Phase 1 fails**: unimol_tools install issue → Docker fallback.
- **Convergence issue**: try smaller model_size (84m), different epochs/lr.
- **OOF MAE > 0.48**: single-model too weak. Try Path 1 (Boltz pose inference) or Path 3 (no-pretrain baseline).
- **All Pearson r > 0.95**: Uni-Mol unexpectedly correlates with existing members. Document; still merge framework.
- **Pool regress**: drop from allow-list, keep framework.

## Testing

- Smoke: 100-compound dataset, 2 epochs pretrain, verify repr extraction works.
- Full pipeline smoke: 2-fold TabPFN on small subset.

## Risks and mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| unimol_tools install fails (DGL/torch version mismatch with cuda 12.x) | Medium | Separate pixi env OR Docker (unimol has docker support). Try conda-forge first. |
| Pretrain model (164m) too large for RTX 5080 16GB | Low | Drop to 84m. 16GB fits 84m fully. |
| `UniMolRepr` after `MolTrain` doesn't load finetuned weights correctly (API mismatch) | Medium | Fallback: use pretrained `UniMolRepr` directly (skip log2_fc pretrain) as Path 3 baseline; add MLP on that repr instead. |
| `cls_repr` embedding is low-rank or collapsed | Low | Unlikely given Uni-Mol's 209M-compound pretraining. Monitor std/mean of repr. |
| OOF regress due to 3D-pretrain feature mismatch with PXR assay | Medium | If so, Path 1 or Path 3 variants may help. Document and pivot. |
| ETKDG fails on bridged or impossible-stereo compounds | Low | Already handled by `db/fix_bridged_stereo.py` in our standardization. 13,136 standardized smiles expected to embed cleanly. |
